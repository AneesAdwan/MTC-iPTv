# دليل الإصدار والتحقق منه (§18، §27 بند 7–8)

> أمر واحد يبني كل المنصّات وينشرها: `scripts/release.ps1`. يُشغَّل في الواجهة (لا في الخلفية)، ويستغرق نحو 8 دقائق.

## 1. قبل الإصدار

1. قسم `## [X.Y.Z-alpha.N]` في `mtc_iptv/CHANGELOG.md` مكتوب (السكربت يتوقف بدونه).
2. لا يعمل إصدار آخر: `Get-CimInstance Win32_Process | ? CommandLine -like '*release.ps1*'` يجب أن يكون فارغًا. إصداران متداخلان يقفلان `mtc_iptv.exe` (خطأ LNK1104).
3. أغلق نسخة البناء فقط إن كانت تعمل (ما تحت `build\windows`)، **لا** النسخة المثبّتة.
4. مفتاح التوقيع موجود (انظر §3).

## 2. التشغيل

```powershell
cd mtc_iptv
powershell -ExecutionPolicy Bypass -File scripts\release.ps1                 # alpha.N+1
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Bump none      # إعادة نشر الرقم الحالي (فشل النشر بعد رفع الرقم)
powershell -ExecutionPolicy Bypass -File scripts\release.ps1 -Bump none -Stable   # 3.0.0 النهائي
```

**ما يفعله بالترتيب، وكل خطوة توقف الإصدار إن فشلت:**

| الخطوة | التحقق |
|---|---|
| رفع الرقم في `pubspec.yaml` | رقم واحد لكل المنصّات (D-17) |
| مفتاح DSA | **المفتاح الخاص يطابق `windows/dsa_pub.pem` المضمَّن في البرنامج**، وإلا يرفض |
| `flutter analyze --fatal-infos` + `flutter test` + `mtc_core` | صفر مشكلات |
| بناء Windows + Android | |
| **فحص الأسرار** في ملفات Windows وكل ملف داخل كل APK | لا مفتاح خاص، ولا `service_role`، ولا `sb_secret_…` |
| المثبّت (Inno Setup) | |
| **توقيع DSA** للمثبّت + **التحقق منه بالمفتاح العام نفسه** | `Verified OK` |
| `SHA256SUMS.txt` | |
| commit + tag + push + GitHub Release | prerelease حتى قبول R1 |
| **الـ appcast** `updates/windows-<channel>.xml` (بعد أن يصبح المثبّت قابلًا للتنزيل) + push | GitHub Pages ينشره خلال دقيقة |

## 3. مفتاح توقيع التحديثات (DSA) — الأهم

- **المكان:** `%USERPROFILE%\.mtc-iptv\dsa_priv.pem` (أو متغيّر البيئة `MTC_DSA_KEY`). **لا يدخل المستودع أبدًا** (`.gitignore`: `*priv*.pem`).
- **المفتاح العام:** `mtc_iptv/windows/dsa_pub.pem`، مضمَّن في البرنامج عبر `windows/runner/Runner.rc`.
- ⚠️ **فقدان المفتاح الخاص = كل نسخة مثبّتة لن تقبل أي تحديث بعده** (§18.3.1). المستخدمون سيضطرون لتنزيل المثبّت يدويًا.
- **النسخة الاحتياطية (مطلوبة من المالك، مرة واحدة):** انسخ `dsa_priv.pem` إلى مكان خارج هذا الجهاز ومحمي: مدير كلمات المرور (كمرفق أو نص)، أو ملف مضغوط بكلمة مرور على OneDrive/Google Drive. لا ترسله بالبريد أو الدردشة.
- **البصمة للتحقق:** `Get-FileHash $HOME\.mtc-iptv\dsa_pub.pem` تبدأ بـ `561B4B839EC9A4C3`.

### تدوير المفتاح (عند الشك بتسريبه فقط)
1. أنشئ زوجًا جديدًا (`openssl dsaparam … gendsa … dsa -pubout`).
2. أصدر نسخة **موقّعة بالمفتاح القديم** تحمل **المفتاح العام الجديد** في `windows/dsa_pub.pem` (عدّل السكربت مؤقتًا ليوقّع بالقديم ويتحقق بالقديم).
3. بعد أن تنتشر تلك النسخة، كل الإصدارات التالية تُوقَّع بالجديد. احذف القديم.

## 4. التحديث داخل البرنامج (WinSparkle)

- **الـ appcast:** `https://aneesadwan.github.io/MTC-iPTv/updates/windows-alpha.xml` (و`windows-stable.xml` بعد R1). البرنامج يختار القناة من رقم إصداره.
- **الفحص:** كل 6 ساعات تلقائيًا، و«تحقق من التحديثات» في «حول»، و«حدّث الآن» في شريط التنبيه وصفحة التحديث الإجباري (G6).
- **الأمان:** WinSparkle ينزّل المثبّت ويتحقق من **توقيع DSA** بالمفتاح المضمَّن، ويرفض أي ملف معدّل، ولا يثبّت إلا بموافقة المستخدم.
- **الإغلاق للتثبيت:** البرنامج يخرج فعليًا عند طلب WinSparkle (حتى للمدير الذي يُخفي النافذة عادة)، بعد إيقاف المشاهدة وإرسال آخر الإحصاءات.

## 5. سيناريوهات الفشل (§18.4)

| السيناريو | ما يحدث | ما تفعله |
|---|---|---|
| انقطاع التنزيل | WinSparkle يلغي، والنسخة الحالية تعمل | لا شيء: يُعاد الفحص لاحقًا |
| توقيع غير مطابق | WinSparkle يرفض ويحذف الملف | تحقق من المفتاح (§3) وأعد الإصدار |
| فشل المثبّت أثناء التثبيت | Inno Setup يتراجع عن الملفات المستبدلة | أعد التشغيل، والنسخة السابقة تعمل |
| البرنامج يعمل أثناء التحديث | يُغلق نفسه، و`CloseApplications=force` احتياط | — |
| نظام قديم | `sparkle:minimumSystemVersion` = 10.0.19044 يخفي التحديث | — |
| **إصدار معيب بعد النشر** | — | **الرجوع للأمام**: أصلح وأصدر رقمًا أعلى فورًا. لإيقاف انتشار المعيب مؤقتًا أعد الـ appcast للإصدار السابق (commit على `updates/windows-alpha.xml`)، واستخدم G6 «الحد الأدنى المدعوم» إن لزم الإجبار |
| لا اتصال | لا يظهر شيء | — |

## 6. بعد الإصدار

- `gh run list --limit 2`: CI أخضر.
- افتح رابط الـ appcast وتأكد أن الرقم الجديد ظاهر (قد يتأخر GitHub Pages دقيقة).
- على جهاز فيه الإصدار السابق: «حول» ← «تحقق من التحديثات» ← يظهر الجديد ← تثبيت ← يفتح بالإصدار الجديد والبيانات كما هي.
