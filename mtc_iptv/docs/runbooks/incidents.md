# الحوادث الشائعة وطريقة التعامل معها (§27 بند 7)

> القاعدة: **لا حذف تلقائي ولا إخفاء تلقائي** (D-14). كل قرار يُتخذ من البرنامج ويُسجَّل في التدقيق.

| الحادثة | كيف تعرفها | ما تفعله |
|---|---|---|
| قناة لا تعمل عند الجميع | بلاغات متكررة (تنبيه A3)، أو «الأقل نجاحًا» في التحليلات | D6 البلاغات ← «جرّب» ← «فحص الروابط». إن تعطّل المصدر: أضف رابطًا بديلًا أو اخفِ القناة (B1). للإخفاء الفوري من كل الأجهزة: G5 «الإخفاء الفوري» |
| انخفاض عام في نسبة النجاح | تنبيه «انخفاض نسبة نجاح التشغيل» | التحليلات ← «حسب الخادم»: غالبًا نطاق واحد متوقف. افحص روابطه (D4) |
| تحديث معيب وصل للمستخدمين | بلاغات بعد إصدار | **للأمام**: إصلاح + إصدار أعلى. مؤقتًا: أعد `updates/windows-alpha.xml` للإصدار السابق — انظر [release.md §5](release.md) |
| خلل يحتاج إيقاف المشاهدة | — | G5 «وضع الصيانة» برسالة. المدير يدخل عاديًا |
| ميزة فيها خلل | — | G5: أوقف الدليل أو التذكيرات أو الإبلاغ أو المشغّل المصغّر، دون إصدار |
| الدليل لا يتحدّث | تنبيه «الدليل لم يتحدّث منذ 48 ساعة» | H2 ← «الدليل» ← شغّل الآن، وراجع E1 (حالة كل مصدر وخطؤه) |
| لا نسخ احتياطية | تنبيه «لا نسخة احتياطية منذ 48 ساعة» | H4: تحقق من المجلد وعبارة المرور، ثم «نسخة الآن» |
| المُجدوِل لا يعمل | «آخر تشغيل» قديم في H2 | البرنامج مفتوح على جهاز المدير؟ «البقاء في منطقة الإشعارات» و«البدء مع ويندوز» مفعّلان؟ (H2) |
| خطأ في بيانات القنوات بعد عملية جماعية | — | H3 التدقيق (قبل ← بعد لكل حقل)، أو H4 استعادة جدول أو **قناة واحدة** من نسخة |
| Supabase لا يستجيب | البرنامج يعمل من الكتالوج المحلي ويعرض «غير متصل» | انتظر، وتابع status.supabase.com. لا شيء يُفقد: المشاهدة من النسخة المحلية |
| فقدان التحقق بخطوتين للمدير | — | [admin-recovery.md](admin-recovery.md) |
| الشك بتسريب مفتاح توقيع التحديثات | — | [release.md §3](release.md) «تدوير المفتاح» |
| مفتاح Supabase العام (anon) | — | **ليس سرًا** (منشور في الموقع والتطبيق). الحماية في RLS ودوال `is_admin()` |
| الشك بتسريب مفتاح الخدمة (service_role) | — | Supabase ← Project Settings ← API ← أعد توليده فورًا. البرنامج لا يستخدمه أصلًا (فحص الأسرار في كل إصدار يمنع وصوله للحزمة) |
