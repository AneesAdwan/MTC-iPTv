# اختبار الترقية من React Native إلى Flutter على Android (§24.6، ADR-16)

> شرط R2: اختبار ترقية فعلي على 3 أجهزة على الأقل (جوال حديث، جوال قديم Android 7–8، TV Box) قبل اعتماد ADR-16.

## ما جُهّز وتحقّق منه آليًا (alpha.20)

| النقطة | الحالة |
|---|---|
| مفتاح التوقيع | ✅ كل APK موقّع بالمفتاح الرسمي نفسه لتطبيق RN (SHA-256 `f9e2e099…c5f7`)، و`release.ps1` يرفض النشر إن اختلف |
| `versionCode` | ✅ `30000 + رقم البناء` (+1000 × المعمارية) = 31019…34019، أعلى من 21 (RN 2.2.5) |
| صلاحية الإنترنت | ✅ كانت **ناقصة** في كل نسخ المعاينة السابقة (Flutter يضيفها لبناء debug فقط) |
| http العادي | ✅ `usesCleartextTraffic` (مصادر IPTV كثيرة http) |
| الروابط العميقة | ✅ `mtciptv://watch/<id>` (Intent ← MainActivity ← نفس قناة Windows) |
| Android TV | ✅ `LEANBACK_LAUNCHER` + بانر 320×180، واللمس غير مطلوب |
| مرحِّل البيانات | ✅ يقرأ `databases/RKStorage` ← `catalystLocalStorage`: المفضلة والسجل والإشعارات. لا يرحّل جلسة المدير، **ولا يحذف شيئًا من بيانات RN**. مُختبر على ملف بنفس البنية |

## ما بقي لـ R2

| البند | السبب |
|---|---|
| تغيير المعرّف `com.mtciptv.preview` ← `com.mtciptv` | بعد نجاح الاختبار أدناه (القرار للمالك) |
| Push (FCM) | `google-services.json` مسجّل لـ `com.mtciptv` فقط، فيُضاف مع تغيير المعرّف |
| PiP، Chromecast | المرحلة 8 |
| D-11 Google Play | مؤجل |

## خطوات الاختبار (لكل جهاز)

1. ثبّت **RN 2.2.5** (`MTC-iPTv-2.2.5.apk` من GitHub).
2. أضف 3 قنوات مفضلة، وشاهد قناتين (السجل)، وانتظر إشعارًا أو أرسل واحدًا من F1.
3. ابنِ نسخة اختبار بالمعرّف `com.mtciptv` **دون نشرها** (تعديل مؤقت لـ `applicationId` + `flutter build apk`) وثبّتها **فوق** RN مباشرة (بدون حذف):
   `adb install -r app-arm64-v8a-release.apk`
4. تحقق: التثبيت قُبل دون حذف · المفضلة بنفس الترتيب · السجل · الإشعارات في صندوق الوارد · التشغيل يعمل · `mtciptv://watch/<id>` من المتصفح يفتح القناة · على TV: يظهر في الشاشة الرئيسية بالبانر ويعمل بالريموت.
5. سجل البرنامج: `adb logcat | findstr "migrated from React Native"`.
6. سجّل النتائج هنا لكل جهاز.

| الجهاز | Android | النتيجة |
|---|---|---|
| محاكي Pixel 7 (x86_64، صفحات 16KB، ترجمة ARM) | 17 (API 37) | 🟡 انظر أدناه |
| محاكي Pixel 2 | 8.1 (x86 32-بت) | ⛔ غير قابل للاختبار: Flutter لا يدعم x86 32-بت إطلاقًا، وتطبيق RN أصلًا ARM فقط. الأجهزة الحقيقية ARM ومدعومة |
| محاكي Television 1080p | 9 (x86 32-بت) | ⛔ للسبب نفسه. يلزم صندوق TV حقيقي (ARM) أو صورة TV بمعمارية x86_64 |
| **محاكي MTC_Android8** (x86_64، أُنشئ لهذا الاختبار) | 8.0 (API 26) | ✅ بعد إصلاح: التثبيت، المزامنة، الدليل، الرابط العميق، **التشغيل بالصورة** (كان يفشل بـ «صيغة غير مدعومة»: mpv يسجّل خطأ فك العتاد ثم يتعافى، والبرنامج كان يعتبره فشلًا نهائيًا) |
| **محاكي MTC_AndroidTV16** (x86_64، أُنشئ لهذا الاختبار) | TV 16 (API 36) | ✅ بعد إصلاحات: نمط التلفاز (قائمة جانبية)، البانر، **الريموت وحده**: إغلاق النافذة بـ OK، التنقل في المحتوى والقائمة الجانبية، فتح الشاشات، تشغيل قناة (الصوت يعمل). الصورة سوداء على هذا المحاكي فقط (محاكاة GPU `ro.hardware.egl=emulation`) — تُؤكَّد على جهاز حقيقي |
| **جوال المالك الحقيقي** (arm64) | حديث | ✅ 2026-10-16: alpha.23 (`arm64-v8a`) يعمل، **الفيديو بالصورة**، وكل شيء سليم — يؤكد أن الشاشة السوداء على محاكيات Android الحديثة من محاكاة الـ GPU فقط (`EGL_BAD_ATTRIBUTE` في `EGL_emulation`). ⏳ نقل بيانات RN 2.2.5 الحقيقية عند الترقية |

### نتائج محاكي Pixel 7 — 2026-10-16

| البند | النتيجة |
|---|---|
| تثبيت RN 2.2.5 الرسمي | ✅ يعمل أول مرة، **ثم ينهار عند كل تشغيل لاحق** على هذا المحاكي (`libreactnative.so` لا يُحمَّل: التطبيق ARM فقط ويعمل بالترجمة). لم يكتب `RKStorage` إطلاقًا، فلا يصلح خط أساس لبيانات RN — يلزم جهاز ARM حقيقي |
| **الترقية فوق RN دون حذف** (`com.mtciptv`، نفس المفتاح، versionCode 30020 > 21) | ✅ قُبلت، و`firstInstallTime` بقي من تثبيت RN (البيانات محفوظة) |
| التطبيق بعد الترقية: مزامنة 441 قناة، الدليل، الإعدادات المركزية، الإعلان، **التشغيل** (`play ch=151 … variants=6`) | ✅ |
| **مرحِّل البيانات على Android نفسه**: ملف `RKStorage` ببنية AsyncStorage الحقيقية في `databases/` | ✅ `favorites=3 history=3 notifications=1`؛ المفضلة بترتيب RN، والسجل في «تابع المشاهدة»، والإشعار في صندوق الوارد، وجلسة المدير لم تُرحَّل، والملف بقي دون حذف |
| الرابط العميق والتطبيق مغلق | ✅ يفتح القناة |
| الرابط العميق والتطبيق يعمل | ❌ ← ✅ **أُصلح**: Flutter كان يعترض الرابط ويعيد للرئيسية (`flutter_deeplinking_enabled=false`) |
| الشريط العلوي تحت شريط حالة النظام | ❌ ← ✅ **أُصلح** (SafeArea + اختبار يفشل بدون الإصلاح) |
| مرحِّل يضع علامة «تم» حين لا يجد الملف (فلا يعيد المحاولة أبدًا) | ❌ ← ✅ **أُصلح** |
| توافق صفحات 16KB (Android 15+) | ✅ لا تحذير لتطبيقنا (ظهر لتطبيق RN) |

### إصلاحات من محاكيي Android 8 وAndroid TV 16 — 2026-10-16

| المشكلة | الإصلاح |
|---|---|
| التلفاز يُعرض بتصميم الجوال (1080p = 960×540 منطقيًا) | سؤال النظام عن وضع التلفاز/leanback قبل أول إطار (`isTv`) |
| نافذة الإعلان لا تُغلق بالريموت (لا شيء مركّز) | زر الإغلاق مركّز تلقائيًا + السهم يبدأ من أول عنصر حين لا شيء مركّز |
| الريموت لا يصل للقائمة الجانبية (الصفحة في نطاق تركيز منفصل) | إن لم يجد السهم شيئًا في النطاق، يبحث في الشاشة كلها (ولا يخرج من نافذة حوار). اختبار يفشل بدون الإصلاح |
| زر مركّز لا يبدو مركّزًا | إطار تركيز على كل الأزرار في وضع الريموت/لوحة المفاتيح فقط (لا عند اللمس) |
| قناة تفشل «صيغة غير مدعومة» على Android 8 | خطأ mpv قبل أول إطار يُمهَل 4 ثوانٍ (يتعافى بالفك البرمجي)؛ رفض المصادقة/404 يبقى فشلًا فوريًا |
